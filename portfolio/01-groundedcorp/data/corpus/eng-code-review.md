title: Code Review and Merge Standard
dept: engineering
doc_type: standard
version: 5.1
---

Every pull request requires at least one approving review from an engineer who is not the author before it can merge.
Changes to authentication, authorisation, payment or data export paths require two approvals, one of which must come from the owning team.
Pull requests should stay under 400 changed lines; larger changes must be split or must state why they cannot be.
Continuous integration must be green, including unit tests, linting and the AI quality gate, before merge is permitted.
Code generated by an AI coding assistant must be reviewed line by line by the submitting engineer, who remains accountable for its correctness.
AI-generated code that touches security controls or handles Restricted data requires an explicit note in the pull request describing what was verified.
Direct pushes to the main branch are blocked; hotfixes follow the same review path with an expedited single approval.
Test coverage must not decrease as a result of a merge.
